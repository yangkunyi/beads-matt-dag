## 为什么失败

### 1. 平台硬限制：飞书不提供"工作台"这种东西

- 机器人按钮的三个入口全废：**自定义菜单**只存在单聊；**群菜单** `chat_menu_tree` 只支持 `chat_mode=group`、
  只能放链接、话题群直接 `232001 type: Topic`；**斜杠面板**要客户端 ≥7.70 且群里实测不弹。
  → 话题群里**唯一能放按钮的载体是消息卡片**。
- **bot 读不到群消息历史**（`230027`，连它自己建的群也不行）→ `/recap` 在群里直接废掉，也无法按话题标题自动绑项目。
- 群里默认只收到 @它 / 回复它的消息 → 想在话题里干活，得先 @ 一下。
- 每次能力升级都卡在**人去开发者后台点**：订阅事件、订阅回调、9 条 Base scope、发版本、Base 可见性。
  桥写得再好也过不去这些人工 gate。

### 2. 交互架构：界面只能塞进卡片，于是必然丑

- 终点是"单聊遥控器 + 群里头卡"两处面板，用户原话：**"有点丑陋了"**。
- 卡片表达力上限很低：流式输出只能 `messages.patch` 整条重写；卡片延迟更新 token 30 分钟只够用 2 次；
  没有终端、没有 diff、没有文件树 —— 而工作台恰恰就是这些东西。

### 3. 工程成本不划算

- 4 323 行、3 个事件 consumer、8 类卡片、每项目一个常驻 pi 进程、Base 镜像、watcher；
  回归面大到一次 `pkill` 自匹配就能把 shell 一起带走。
- 验证只能靠合成点击与自测脚本，真实交互仍要人肉点。

### 4. 方法：最该记住的一条

- **先找现成前端，再造桥。** `agegr/pi-web`（6 357★，2026-03 就在）与 pi 共用 session 文件，`npx` 一行能跑，
  从第一天就满足"手机上接着这段对话干"。
- 我的调研排错了序：用 npm 元数据排序，把 6★ 的 `@hyperdreamer/pi-webui` 排成第二选项，
  漏掉了 6 357★ 的那个 —— **排序错的调研比没调研更糟**，它给了个自信的错误答案。
- 沉没成本把"换个现成前端"压到第 13 个 ticket；它本该是第 0 个。
